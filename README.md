# Diverge — спортивная аналитика v12

Мобильное приложение по дизайнам «Бет.pdf»: обязательные вводные истории, единый вход через Telegram, каталог после входа, анализ матчей, пакеты и подписка, профиль, новости, ежедневные монеты и колесо фортуны. Основная платформа — Telegram Mini Apps.

Это статический UX-прототип. По прямой просьбе владельца служебные пометки удалены из интерфейса. Внутри остаются вымышленные события/источники, подготовленные ответы и локальные операции; настоящие платежи, SMS, AI-запросы и Telegram-напоминания не выполняются. Доступ и баланс не защищены сервером.

## Запуск и проверка

Node.js 22.12+ и Microsoft Edge для Playwright:

```powershell
npm ci
npm run dev
```

Адрес http://localhost:5173/ . С запущенным dev server:

```powershell
npm test
npm run test:e2e
npm run test:design
npm run test:wheel
npm run test:polish
npm run test:mobile
npm run test:telegram
npm run test:telegram-window
npm run build
node scripts/check-build.mjs
```

`test:e2e` и `test:experience` запускают `scripts/check-rewards.mjs`: обязательное знакомство, незакрываемый Telegram-вход, отсутствие гостевого/телефонного обхода, согласие/отказ передачи номера, старые телефонные сессии, семь ежедневных наград, колесо/призы, промокод и повторная активация, копирование приглашения, купон, Telegram-профиль, покупки/подписка, история/факторы/чат и 35 сочетаний страниц с размерами 320×568, 390×844, 430×932, 768×1024, 1440×1000. `DEMO_URL` меняет адрес, в том числе на публичный. Снимки — `tmp/rewards-v9/`.

`test:mobile` проверяет анимационные сцены и последовательность текста, тап/свайп, центрирование/точки/колесо слайдеров, поиск и 55 мобильных композиций. `test:design` — клавиатуру, фокус и reduced motion. Telegram-проверки используют настоящий SDK и синтетические launch/native bridge: это не проверка физического iOS/Android Telegram. `check-build.mjs` сам запускает production-сборку в подпапке `/rakurs-demo/` и проверяет ресурсы/покупку.

## Истории и награды

Первый визит в конкретном браузере/WebView открывает четыре вводные истории поверх всего приложения. Пропуск и закрытие отключены; будущий сегмент недоступен до прохождения предыдущих. После завершения сохраняется `rakurs:pdfOnboardingSeen`; следующие запуски ведут в каталог. Крайняя правая история «О приложении» повторяет знакомство и не имеет обводки. Информационные истории получают градиентную обводку до открытия; новые публикации добавлять в начало `NEWS_ITEMS` в `RewardsUI.jsx` с новым стабильным id. Пока это контент из репозитория, серверной загрузки нет.

Окно монет автоматически появляется один раз за календарные сутки Europe/Moscow через 1,4 с после входа/завершения знакомства и закрытия других диалогов. Другой диалог отменяет ожидающий таймер; показ фиксируется только при появлении. Панель плавно выезжает за 0,72 с. Закрытие окна учитывается как показ, но награду можно получить позже через баланс слева от аватара. Награды: 10, 15, 15, 20, 20, 25, 25 — всего 130 за семь дней подряд. Получение ограничено 24 часами от `lastClaimAt`, независимо от полуночи. После получения кнопка показывает «Следующая награда» и HH:MM; время сохраняется при перезапуске. Пропуск 48-часового окна сбрасывает серию, накопленный баланс сохраняется. Старые записи только с датой мигрируют через полночь Europe/Moscow. Календарный автопоказ и 24-часовое получение — разные ограничения. После седьмого дня начинается следующий цикл.

Монеты теперь расходуются на колесо, а не на прямую покупку прогноза/скидки. Начальная цена — 10 за вращение; 130 за неделю остаются суммой наград. В профиле — колесо, промокод и приглашения. В заказе матча остаются рубли или ранее полученный доступ.

Текущая механика и состав призов описаны в разделе v12 ниже: вертикальная рулетка, отдельные сохранённые выигрыши, ограниченные по сроку новые купоны/прогнозы, техника и пополнение баланса. Максимальный действующий купон применяется к пакету от двух прогнозов и расходуется один раз. Старые постоянные кредиты/купоны, купленные доступы и монеты сохраняются.

Стартовый промокод для проверки frontend: `DIVERGE10` — 10 монет один раз на браузер. Нормализуются регистр/пробелы, есть ошибочный/повторный код. Это локальная конфигурация, а не защищённый production-промокод. В приглашениях копируется `https://t.me/demobett_bot?startapp=ref_<TelegramId>`; учёт приглашений и бонусы ещё не реализованы и отмечены «к релизу». Требуется настройка Main Mini App и серверная обработка подписанного start_param. [Telegram direct links](https://core.telegram.org/bots/webapps#launching-the-main-mini-app).

Внешний вид рулетки обновлён по полученным референсам. Экономика/шансы ещё предварительные; реферальный дизайн и размер вознаграждения пользователь пока не задавал. `npm run test:wheel` проверяет вертикальное движение, остановку/начисление, повторный клик и reload посреди анимации. Снимки `tmp/roulette-v12/`.

## Вертикальная рулетка v12

Круглый диск заменён лентой по пользовательским референсам. Idle медленно показывает призы; вращение быстро проходит ленту и замедляется к выбранному результату, затем отдельный экран выигрыша со сроком/использованием. Списание и приз сохраняются вместе до анимации; перезагрузка восстанавливает незавершённое открытие без повторного начисления. В профиле — «Мои призы» и каталог.

Предварительная внутренняя конфигурация: монеты5/15, скидки10/20/30%, прогноз,25 ₽ на баланс, iPhone/MacBook. Веса в rewards.js:20/25/16/8/18/8/0,08/4,84/0,08%, всего100. Это не опубликованные условия реальной акции. Новые купоны действуют24ч, прогнозы7дней; старые бессрочные доступы/купоны и история мигрируют. Истёкшие/использованные призы остаются в коллекции со статусом. Баланс выигрыша применяется к прогнозам и пакетам с переключателем; пример25 ₽ сокращает остаток199 ₽ до174 ₽. Указанный выигрыш зачисляется один раз, повторное открытие не добавляет денег. Техника сохраняется как приз, получение прямо отложено к релизу, без отправки сообщений и обещания оформленной доставки.

Новые файлы RouletteUI.jsx/roulette.css загружаются отдельно. PNG atlas public/images/prizes/prize-atlas-v1.png создан встроенным image_gen; точный промпт и карта ячеек в public/images/prizes/manifest.json. Исходники скриншотов не изменены. Для Windows dev включён polling: в длинной сессии обнаружено, что native file notifications пропускали быстрые изменения JS. Это настройка разработки, не production.

`test:wheel` теперь проверяет вертикальную ленту, остановку, TTL, отсутствие дублей, reload и использование сохранённого прогноза. Backend перед релизом должен выбирать приз и атомарно вести баланс/инвентарь/сроки, учитывать остатки физических призов и процедуру получения; сейчас всё локально. Снимки tmp/roulette-v12.

## Доводка v11

Тап/свайп/удержание работают в онбординге и новостных историях. Крайняя правая плитка называется Onboarding. Третья сцена анимирует число 0→74, постоянные движения мягче; reduced motion выключает их. Из колеса убраны раскрывающиеся правила и последние призы, внутренняя история сохраняется.

Live / Pre-match без TOP. Процент карточки подписан шансом победы первой команды по оценке до матча; до открытия — «Прогноз на матч / Статистика и факторы». Эмодзи у всех пяти видов спорта используют системный emoji font (Apple на iPhone, системный fallback на остальных). Поиск — встроенное поле по лупе на главной; таб поиска убран, /search остаётся совместимым. На мобильных плавающая капсула с тремя круглыми кнопками; финальный референс пользователь пришлёт позже. `test:polish` проверяет задержку/сохранение таймера, касания, counter, капсулу, inline search при уменьшении viewport под клавиатуру и юридические ссылки; снимки tmp/polish-v11. Это эмуляция клавиатуры, физические iOS/Android отдельно не проверены.

## Вход, доступ и цены

Единственный способ — «Войти через Telegram». Сначала обязательное знакомство, затем вход; каталог не монтируется до входа. Нельзя обойти экран крестиком, Escape, фоном, native Back, прямой ссылкой или reload. После выхода снова показывается вход без повтора знакомства. Внутри Mini App профиль читается из SDK и сохраняется локально; в обычном браузере открывается существующий бот, фиктивной регистрации нет. Это ещё не серверная проверка initData. Старые телефонные профили больше не авторизуют, но покупки/монеты/избранное/кредиты этого устройства сохраняются.

В профиле необязательная кнопка «Поделиться номером» вызывает native `requestContact()` (API 6.9+). Нет ручного ввода, паролей, SMS-провайдера. Отказ не ограничивает доступ; обрабатываются ожидание, согласие, отмена и старые клиенты. Callback содержит только согласие, сам контакт получает бот: обработчик и привязка к аккаунту появятся на серверном этапе. Сейчас сохраняется только флаг согласия, не номер. [Telegram Mini Apps API](https://core.telegram.org/bots/webapps#initializing-mini-apps).

Полный анализ 199 ₽, месяц всех событий 1000 ₽. Пакеты исходов 3/5/10 за 29/129/259 ₽; пакеты полного анализа 1/3/5 за 199/549/899 ₽. Исходы не открывают факторы и чат. Баланс/карты/платежи имитируются локально; реальные реквизиты, документы и токены не запрашиваются. Вероятности и факторы согласованы до 100%, неподтверждённые социальные гипотезы не меняют расчёт.

Ключи состояния с префиксом `rakurs:`: `pdfOnboardingSeen`, `rewardsWallet`, `readNews`, `demoUser`, `analysisCredits`, `outcomeCredits`, `outcomePurchases`, `demoBalance`, `demoTransactions`, `demoCards`, `generalChat`. Технические имена старых ключей сохранены для совместимости. Покупки `aiPurchases`, подписка `aiSubscription`, `favorites`, `eventChat:<id>` и meaningful legacy-ссылки продолжают работать. Очистка данных или другое устройство создают новое локальное состояние.

## План переноса и нагрузки — сервер 4 vCPU / ~8 ГБ / ~90 ГБ

Это исходные характеристики от владельца, а не измеренный свободный ресурс: на сервере уже живёт другое приложение. Провайдер/виртуализация, канал, IOPS и текущие CPU/RAM/диск неизвестны. Разумная стартовая гипотеза — использовать этот сервер для первого backend, затем принять решение по измерениям. Сервер не подключался; текущая публикация остаётся на Pages. GitHub — репозиторий/CI, Pages — текущий статический хостинг, собственный сервер — будущая среда приложения. GitHub Pages не предназначен для коммерческого SaaS/платежных сайтов; до реального релиза перенос необходим. [GitHub Pages limits](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits).

Нельзя перевести характеристики в гарантию «на 100/1000/5000 человек». Важны одновременно активные пользователи, запросы/сек, стоимость операций, лимиты БД/AI/источников и скорость канала. Чистый пример при одном API-запросе на пользователя в 10 секунд:

| Одновременно активных | Средних API-запросов/сек при этом допущении |
|---|---|
| 100 | 10 |
| 1000 | 100 |
| 5000 | 500 |

Это арифметика, не результаты теста. Массовый вход создаёт дополнительные запросы авторизации/каталога/картинок. Один AI-запрос может обходиться дороже множества чтений готового прогноза. Общий анализ матча следует рассчитывать один раз на снимок данных и кэшировать, а не запускать модель заново для каждого посетителя.

Предлагаемая схема второго этапа:

1. Отдельный HTTPS-домен/виртуальный хост, отдельные контейнеры/сеть/тома/секреты. Проверить существующий reverse proxy, порты и резервные копии другого приложения. Ввести CPU/RAM-лимиты и ротацию логов; общий VPS остаётся общей точкой отказа. [Docker resource constraints](https://docs.docker.com/engine/containers/resource_constraints/).
2. Статический frontend отдавать с кэшированием/CDN, при желании с нашего сервера как origin. API/бот, PostgreSQL и фоновый worker — отдельные процессы. Очередь для рассылок/обновлений/долгих задач; общие готовые прогнозы кэшировать. Файлы/резервные копии не складировать бесконечно на 90 ГБ.
3. Бэкенд проектировать без локальных пользовательских сессий на конкретной копии. Аккаунты/кошелёк/доступы в БД; транзакции, идемпотентность покупок/наград, индексы и ограниченный пул подключений. Лимиты частоты запросов и отдельный бюджет AI защищают от всплеска расходов.
4. Перед рекламой тестировать реалистичные сценарии на тестовой среде ступенями: 100, 1000, 5000 активных, плюс резкий запуск/долгая нагрузка. Замерять p95 времени ответа, долю ошибок, CPU/RAM, БД/очереди и канал; согласовать критерии до теста. Ориентир для лёгкого API, требующий подтверждения: p95 ≤500 мс, ошибки <1%, без роста очереди и с запасом ресурсов. AI-вызовы измерять отдельно. Не нагружать рабочий сервер другого приложения без отдельного плана. [k6 API load testing](https://grafana.com/docs/k6/latest/testing-guides/api-load-testing/).
5. Для роста добавить вторую копию API за балансировщиком. Две копии на одном VPS помогают обновлять процесс, но не переживут отказ/перезагрузку всего VPS; для этого нужны разные машины и отдельно продуманная доступность БД. [NGINX load balancing](https://nginx.org/en/docs/http/load_balancing.html).

Вертикальный апгрейд — больше CPU/RAM у одной VM; необходимость остановки зависит от провайдера. Например, DigitalOcean требует выключения Droplet для resize. Для почти незаметного перехода поднимают новую копию/машину, проверяют готовность, переключают трафик и дают старым запросам завершиться; миграции БД должны быть совместимы со старым и новым приложением, сессии — общими. Базу данных нужно масштабировать отдельно. [Resize documentation](https://docs.digitalocean.com/products/droplets/how-to/resize/).

«Резиновое» облако — автоматическое добавление копий, не бесконечное мгновенное увеличение одного VPS. Нужны min/max, метрики, балансировка, запуск/прогрев, предел бюджета. Перед известной рекламой держать готовый запас/увеличить минимум заранее: autoscaling реагирует с задержкой и не устраняет предел БД/внешнего API. Пока выбор конкретного облака/тарифа отложен до данных провайдера и измерений; Kubernetes для первого запуска не требуется. [Autoscaling pools](https://docs.digitalocean.com/products/droplets/how-to/use-autoscale-pools/), [instance warmup](https://docs.aws.amazon.com/autoscaling/ec2/userguide/ec2-auto-scaling-default-instance-warmup.html).

Порядок переноса: аудит сервера → staging/HTTPS/API → подписанная Telegram-авторизация/БД/бот → нагрузочная проверка → резервные копии и rollback → публикация frontend на новом домене → обновление URL Mini App. Покупки/избранное сейчас хранятся на origin Pages: другой домен не получит этот localStorage автоматически. Перед сменой адреса решить, нужен ли безопасный экспорт/импорт или привязка серверной миграции к Telegram ID; не обещать автоматический перенос между доменами.
